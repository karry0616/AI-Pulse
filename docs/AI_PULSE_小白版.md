# AI Pulse 小白版说明书

> 写给完全不懂技术的读者。没有代码，没有术语堆砌，读完你能明白：这东西是干什么的、凭什么可信、能给你带来什么、它做不到什么。
> 更新日期：2026-10-30

## 一、一句话说明

**AI Pulse 是一个「AI 行业的自动情报员」：它每天替你读上百条科技新闻，挑出真正重要的事，写一份摘要，发现风险时先报警、等人点头才推送。**

你可以把它想成一个不知疲倦的实习编辑：会扫新闻、会做分析、会写稿，但**最后发不发，必须由人签字**。

---

## 二、它解决什么问题

| 痛点 | 具体表现 | AI Pulse 的做法 |
| --- | --- | --- |
| 信息太多 | 每天几十个网站、上百条 AI 新闻，看不过来 | 自动从多个公开新闻源抓取，去重后只留下当天新内容 |
| 真假难辨 | 标题党、重复报道、以讹传讹 | 同一条新闻的多家报道会被合并成一条「事件线」；分析结果必须能对回原文标题 |
| AI 会胡说 | 大模型可能编造数字、夸大风险 | 关键数字由程序重新计算；分析稿要过一道「审稿人」，连续不合格就退回规则模式 |
| 不敢全自动 | 风险预警一旦误发，可能造成真实损失 | 只生成「待审批」草稿，必须人工点「通过并推送」才会发到飞书/钉钉 |

一句话：**它负责「看得全、看得快」，人负责「拍板」。**

## 三、它每天怎么工作（编辑部比喻）

一次完整的运行，就像编辑部出刊：

```
① 记者（Collector）     跑现场：从各个新闻源抓取当天资讯，整理成条目
        ↓
② 分析师（Analyst）     写稿：判断热度、情感（利好/利空）、风险、行业成熟度
        ↓
③ 审稿人（Critic）      挑毛病：检查格式、数字范围、标题能否对回原文
        ↓ 不合格就打回重写（最多 3 次）
④ 编辑（程序规则）      校对：热度、正面占比等关键数字用代码重算，防止模型夸大
        ↓
⑤ 主编（你）            签字：有风险预警时，必须人工点「通过」才会推送
```

三个角色不是三个真人，而是程序里三个各司其职的「AI 岗位」。这样设计的好处是：**写稿的不能自己给自己打分**，审稿的只认硬标准。

如果 AI 服务临时不可用（没配置密钥、网络断了、接口报错），系统会自动切换到「规则模式」：不调用大模型，用关键词和固定模板给出保守结论，并在页面上明确标注「当前为降级模式」。**宁可说得保守，也不假装聪明。**

## 四、三个「防忽悠」设计

1. **数字不许 AI 自己说了算**
   热度分、正面新闻占比这类关键数字，程序会用抓到的资讯重新算一遍。如果 AI 报的数与程序算的差太多，以程序为准，并在日志里留痕。

2. **每句话都要能对回原文**
   摘要里提到的新闻标题，必须能在当天抓到的资讯里找到。找不到就算「幻觉」，审稿环节直接打回。

3. **不确定就降级，不硬撑**
   模型调用失败、格式不合格、连续 3 次改不好，系统不会勉强输出，而是切换到规则模式，并在页面上标红提示。**降级不是故障，是设计好的安全网。**

## 五、实际成绩（都是可复现的）

| 指标 | 数字 | 白话解释 |
| --- | --- | --- |
| 自动化检查 | **191 项全部通过** | 每次改代码，机器会自动跑 191 个检查，确认没有把原来能用的功能改坏 |
| 代码体检覆盖率 | **77%** | 将近八成的代码路径都被自动检查过；页面部分达到 86%–100% |
| 单条新闻场景可用率 | **88.9% → 100%** | 当天只抓到 1 条新闻时，原来的方案经常交不出合格稿；补入最近存档后稳定合格 |
| 方案对照实验 | 三 Agent 的负面判断误差 **0.67**，单次 AI 直出为 **1.0** | 误差越小越准；多角色流程确实比「一次问答」更靠谱，代价是耗时约多 1.6 倍 |
| 降级场景 | 打回次数从 3 次降到 **1 次** | 规则模式不再做无用功，日志更干净、等待更短 |

> 这些数字来自项目里的验证报告和对照实验脚本，不是宣传口径。报告同时记录了**修复前的失败数据**，方便核对改进是否真实。

## 六、你打开页面能看到什么

- **今日概览**：热度分、正面/负面占比、抓取条数
- **核心动态**：当天最重要的几条新闻摘要
- **事件线**：同一件事的多家报道合并成时间线，看出事情在往哪个方向走
- **风险预警**：负面信号汇总；有待审预警时出现「通过并推送 / 驳回」按钮
- **运行指标**：最近运行成功率、降级比例、抓取成功率、P50/P95 耗时（P95 可以理解为「最慢的那一小部分请求有多慢」）
- **执行轨迹**：这次分析每一步做了什么、AI 调用了几次、花了多少 token、被审稿人打回几次
- **日报导出**：每次运行自动生成一份 Markdown 日报

## 七、它不会做什么（诚实边界）

- **不会替你判断商业价值**：它只做信息聚合与风险提示，不构成投资建议。
- **不会自动群发**：风险预警必须人工审批；这是有意设计的，不是没做完。
- **不保证抓到所有新闻**：只覆盖配置里的公开 RSS 源，付费墙、登录墙内容抓不到。
- **离线/降级时结论较粗**：规则模式只看关键词，不做语义理解，适合「先别漏」，不适合「精细研判」。
- **真实推送需要你自己配置**：飞书/钉钉机器人地址属于敏感配置，项目里不会预置，验证时也没有真的对外发送。

## 八、五分钟跑起来（给愿意动手的人）

```powershell
# 1. 装依赖（项目根目录）
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt

# 2. 启动页面（不配 AI 密钥也能跑，会自动进入规则模式）
.\.venv\Scripts\streamlit.exe run app.py

# 3. 打开浏览器，点击「立即更新情报」
```

想接入真实 AI：复制 `.env.example` 为 `.env`，填入 `DEEPSEEK_API_KEY`。
想接入飞书/钉钉：在 `.env` 填 `WEBHOOK_URL`；飞书卡片按钮还需 `PUBLIC_BASE_URL` 和回调配置。

## 九、小词典

| 词 | 白话解释 |
| --- | --- |
| RSS | 网站提供的一种「新闻目录」，程序可以定时读取，不用爬网页 |
| LLM / 大模型 | 能理解和生成文字的 AI，例如 DeepSeek |
| Agent / 智能体 | 被赋予一个明确岗位和任务的 AI 程序；本项目有三个岗位 |
| Prompt | 给 AI 的指令模板，相当于「工作说明书」 |
| RAG | 让 AI 先查资料再回答，减少凭空编造 |
| Critic | 审稿人角色，只做格式与事实核验，不打感情分 |
| 降级 | 高级方案不可用时，自动退到保守但可靠的备用方案 |
| Token | AI 计费和计量的单位，可以粗略理解为「字数」 |
| P50 / P95 | 50%/95% 的请求能在多少时间内完成；P95 用来衡量「慢的那批」 |
| HITL | Human-in-the-loop，人在回路：关键动作必须人工确认 |

## 十、常见疑问

**问：它会不会自己乱发消息？**
答：不会。风险预警默认只存为「待审批」，必须人工点通过；推送失败还会自动重试，仍失败就标记失败并保留记录。

**问：AI 说的数字可信吗？**
答：关键数字会被程序重算并覆盖；新闻标题要能对回原文；不合格的稿子会被打回，连续不合格就降级。

**问：没有 AI 密钥还能用吗？**
答：能。系统会进入规则模式，功能完整、结论保守，页面上会明确提示当前不是 AI 模式。

**问：数据存在哪里？**
答：本地一个 SQLite 数据库文件，不上传云端；删除该文件即清空全部数据。

**问：这套东西能直接商用吗？**
答：目前是个人项目级别的成熟度：核心链路有自动化回归，但真实推送、长期运行、多人协作仍需按你的环境做上线验证。
